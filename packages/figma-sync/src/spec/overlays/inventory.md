# Inventaire des surcouches — app, site, DM

Relevé du code au 25/09/2026 (`<Dialog`, `<AlertDialog`, `<Sheet`, `<Drawer`, `<Popover`, `<DropdownMenu`,
`<ContextMenu`, `<Tooltip`, `<ModalPortal`, `window.confirm(`, `role="dialog"`/`role="menu"`, `toast.*`,
`CommandDialog`), fichiers de test et de stories exclus. `AlertDialog`, `Drawer`, `CommandDialog`,
`ConfirmationDialog` et `ActionDialog` : **aucun rendu** dans les trois surfaces (RUX-23 le constate).

Une ligne = une surcouche ouverte par le code. La colonne **Spec / statut** porte l'identifiant de sa spec
(`src/spec/overlays/*.ts`) ou la raison pour laquelle elle attend. La garde `overlay-inventory.test.ts` lit ce
fichier : chaque identifiant cité existe au registre, chaque spec du registre est citée, chaque ligne sans spec
dit pourquoi.

Priorité du lot (≤ 40 specs) : **toutes** les confirmations destructives et `window.confirm`, les formulaires qui
créent ou envoient, puis un représentant par famille (panneau, menu, bulle, info-bulle, toast, palette).

`feat/figma-sync-overlays-a-l` et `feat/figma-sync-overlays-m-z` (25/09/2026) referment le reste de l'inventaire `app` (`apps/web/src/features/*`) : la première sur `[a-l]*` (`src/spec/overlays/app-a-l.ts`, 103 nouvelles specs), la seconde sur `[m-z]*` (`src/spec/overlays/app-m-z.ts`, 22 nouvelles specs — confirmations, formulaires qui créent ou envoient, doctrine facturation/permissions). Le reste REGROUPÉ (`= spec X`) quand strictement identique à un représentant déjà maquetté, ou en attente nommée sinon.
