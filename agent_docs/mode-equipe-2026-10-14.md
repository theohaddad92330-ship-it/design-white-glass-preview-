# Tracker — Mode équipe (ESN multi-utilisateurs) — 14/10/2026

Épopée : #4158 · base : 1fa317722d (origin/main 14/10) · source : demande Louis 14/10 + audit code + benchmark marché.

## 1. Décisions

- ⚠️ RENVERSEMENT daté (Louis 14/10/2026) : le tableau `/team` n'est plus fait de sept sections repliées par défaut (#1809, #2405.3 du 22/09). Pyramide inversée, « À traiter » toujours ouvert en tête (lot L7).

### Décisions Louis du 14/10 (QCM)

- **Sidebar** : entrée « Équipe » de 1er niveau dès **2 membres actifs**, retirée de Pilotage. ESN solo : rien dans la sidebar ni dans Pilotage ; Réglages › Équipe reste (c'est là qu'on invite le premier collègue).
- **Onboarding** : un membre qui arrive AVANT que l'admin ait décrit l'entreprise **attend l'admin** : il ne répond qu'à ses questions perso, un bandeau dit que l'admin n'a pas encore décrit l'ESN, et il n'écrit aucune réponse entreprise.
- **Transfert de propriété** : **back-office seulement** (dashboard-manager). Nouveau propriétaire choisi parmi les admins, abonnement et crédits déplacés, l'ancien propriétaire devient admin.
- **Notifications entre collègues** : **dans l'app + e-mail opt-in**, désactivé par défaut. Jamais rien vers un prospect.

### Tranché sans Louis (défaut conservateur)

- Droits : seuls owner et admin invitent, retirent ou promeuvent un admin ; sales_ops gère les rôles non admin.
- Visibilité : tout reste visible de l'équipe par défaut. Le privé ne concerne que projets/besoins/missions (#4128) : un objet privé ne fait aucune ligne chez qui n'a pas les droits.
- Démo : l'espace démo reçoit des collègues fictifs (craft rule n°9) pour montrer le mode équipe.
- Benchmark : les 15 recommandations sont prises, sauf ce qui heurte la doctrine (aucune probabilité, aucun envoi automatique, aucun classement nominatif).

## 5 trous les plus graves

1. Escalade de privilège (2b) : tout `team:manage` (sales_ops) invite/retire des admins ; WTS:212, 431.
2. Pas de transfert de propriété (2e) : l'owner ne peut ni partir ni être remplacé.
3. Checklist du plan d'action lue par `user_id` (4c-i, action-plan-items.service.ts:951) + délégations non libérées au retrait (2d) : le travail d'un collègue est invisible/faux sur la fiche compte.
4. Zéro notification de collègue (5e) : assignation, délégation, mention muettes ; mention stockée sans effet (5d).
5. Invitations périmées qui bloquent des sièges, pas de renvoi (1c, 1d) ; plus onboarding membre-avant-owner qui crée deux fiches entreprise divergentes (3b/3c). Hors top 5 : démo mono-membre (9), e2e multi-compte skippé (10), `sequence-templates.service.ts:103`.
