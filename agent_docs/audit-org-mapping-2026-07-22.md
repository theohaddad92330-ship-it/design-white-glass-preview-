# Audit — Agent Organigramme / Account Mapping vs code en production

**Date** : 2026-07-22 · **Référence** : `BELLUMAI_ANNEXE_ORGANIGRAMME_ACCOUNT_MAPPING_2026-07-21.pdf` (32 p.)
**Base auditée** : `origin/main` @ `5d1be338` (« combler une zone blanche sans rejouer le dossier », #712).

Méthode : lecture de l'annexe par tranches, puis vérification dans le code. **Aucun verdict « fait » n'est
posé sans une ligne de code, un champ de contrat, un endpoint ou une chaîne i18n cité.** Règles appliquées :

- un champ **présent dans un contrat mais jamais rempli** par le pipeline = NON LIVRÉ ;
- une donnée **émise mais jamais affichée** = NON LIVRÉE ;
- `agent_docs/org-mapping-plan.md` a été traité comme une piste, pas comme une vérité (plusieurs de ses
  « FAIT » sont ici requalifiés en PARTIEL, voir §4).

---

## 1. Résumé exécutif

Le squelette est réel et de bonne facture : contrat `OrgGraph` complet, moteur de confiance déterministe,
resolver, validateur d'émission, assembleur câblé dans le pipeline live, persistance versionnée, 4 vues
dans l'UI, garde-fou board froid, recherche ciblée par famille × niveau, recalcul de chemin. **Ce qui
manque n'est pas de la plomberie : c'est la matière que ce squelette est censé transporter.**

Les cinq constats structurants :

1. **Aucun edge ne peut être `verified` en production.** L'assembleur crée exactement UNE source par edge
   (`org_graph_assembler.py:293`, `:307`) ; le maximum atteignable par la formule p14 est **70/100**
   (registre 30 + titre 15 + même org 15 + fraîcheur 10), le seuil `verified` étant 90
   (`org_confidence.py:42`). La vue n°1 « organigramme vérifié » est donc **structurellement vide**.
2. **Aucun edge `reports_to` ne se résout.** Le prompt demande `reportingTo` = _« titre du N+1 »_
   (`bellum_contacts.py:104`), l'assembleur le cherche dans un index **nom complet → id**
   (`org_graph_assembler.py:299-300`). Le seul lien émis en pratique est `member_of` (personne → entité).
   Il n'y a donc **pas d'organigramme**, seulement un rattachement.
3. **Aucun nœud ne porte de source ni de date.** `sources` est écrit en dur à `[]` sur les entités
   (`:217`) et sur les personnes (`:263`) ; les `sourceIds` des edges pointent vers des identifiants
   synthétiques (`s-{pid}-ent`) **qui n'existent dans aucun enregistrement** de source. Le critère DoD
   « chaque nœud et edge porte source, date, statut et confiance » n'est atteint que sur la confiance.
4. **Le prompt v2 de l'annexe (p23-p28) n'existe pas.** `bellum_organigramme.py` est le prompt legacy ;
   aucune occurrence de `hierarchyEdge`, `influenceEdge`, `OrgGraphV2` dans `apps/ia/app/prompts/`. Le
   graphe est reconstruit _a posteriori_ par un assembleur déterministe, donc la carte d'influence, le
   sponsoring de programme et la posture (stance) ne sont **jamais produits** par personne.
5. **Le filtre entité / métier / niveau / rôle / projet / confiance (DoD n°3) n'est nulle part.** Zéro
   `filter` dans `OrgGraphViews.tsx`.
