**134 exigences, et le grain est un jugement, pas un fait.** Une exigence = une ligne de tableau de
_spécification_ (une règle, un comportement, un objet à livrer), ou un énoncé normatif de paragraphe — une
phrase qui dit ce que le produit doit faire, refuser ou afficher. **Une énumération de VALEURS à l'intérieur
d'un élément compte pour UN** : les quatre modes de panne du §2.4 sont le critère d'acceptation de « chaque
source déclare son mode », pas quatre exigences ; les six fenêtres du §3.5 sont le contenu de « neuf fenêtres
par type », pas six. À l'inverse, les six sous-règles du principe d'anonymat (§5.3, l.495-498) sont comptées
séparément parce que ce sont six mécanismes distincts, chacun vérifiable seul dans le code — et cinq d'entre
eux tiennent effectivement à une clause SQL différente. Un lecteur cohérent mais différent obtiendra 115-160 ;

`bellum_` — les 18 colonnes `domain_taxonomy__*` (7), `domain_gap__*` (4), `talent_supply__*` (4) et `tjm__*`
