#### Ce que le prompt de l'organigramme ENVOIE réellement au modèle

Deux prompts tournent en parallèle en Phase 3 (`apps/ia/app/services/classification.py:398`,
`classify_contacts_and_organigramme`, appelée par `apps/ia/app/agents/classifier.py:105`, lui-même appelé

`apps/ia/app/graph/nodes.py:classify_node` — run complet) :

**`bellum_organigramme`** (`apps/ia/app/prompts/bellum_organigramme.py`) — système construit à
`classification.py:199` :

```python
org_system = bellum_organigramme.build_system_prompt(profile) + feedback_block
```

`build_system_prompt` (l.25-104) interpole réellement :

- `SELLER_CONTEXT` : nom/taille/offres/secteurs/personas/cycle de vente de l'ESN (`profile_data`, jamais
  du compte cible) ;

  `technical_buyer` (l.70) — **change réellement selon le portefeuille d'offres du vendeur** (voir §9,
  item 118) ;
- `feedback_block` (`classification.py:199`, calculé l.431 via `feedback_directives_block(req.
account_feedback)`, `apps/ia/app/services/account_feedback.py:27`) : **""** si aucun retour utilisateur
  enregistré sur le compte, sinon un bloc `RETOURS UTILISATEUR SUR CE COMPTE` citant chaque retour
  verbatim.

Le prompt utilisateur (`build_user_prompt`, l.107-232, appelé `classification.py:200`) interpole :

- `CONTACTS: {contacts_str}` — **`contacts_str = json.dumps(to_enrich, ...)` où `to_enrich =
strip_protected_criteria(ranked)`** (`classification.py:447-448`). C'est le texte RÉELLEMENT envoyé,
  pas un gabarit : chaque contact du compte cible, moins les clés protégées.

- `RELATIONSHIP_CONTEXT` / `SIGNALS` / `INTERNAL_MEMORY` : rendus « non fourni » si absents
  (`build_user_prompt` l.126-128), jamais devinés. `INTERNAL_MEMORY` porte `req.account_feedback`
  brut (`classification.py:491`, `memory=req.account_feedback`) — mémoire de corrections GÉNÉRALE
