Demande de Louis (10/10, #3885) : « ajouter Indeed, les offres LinkedIn, d'autres offres, Malt, etc. — tout ce
qui peut nous apporter des offres, des signaux, des besoins d'entreprise ; ratisse tout ».

Cadre (doctrine `c79_collecte_large_mais_propre`, `agent_docs/doctrine.md`) : on collecte **LARGEMENT, tant que
c'est PROPRE** — API officielles, flux publics, partenaires de données sous contrat. **Jamais** de scraping qui viole
des CGU ou contourne une authentification (LinkedIn, Indeed en HTML = NON). Sans clé = no-op STRICT. Un contrat
d'API non vérifiable ne se devine pas. Nos fournisseurs ne se nomment jamais à l'utilisateur.

Légende « apporte » : **O** = offre d'emploi (recrutement, donc besoin de bras), **S** = signal (événement daté),
**B** = besoin explicite (mission, appel d'offres).

## Comment les nouvelles sources s'insèrent (contrat existant, rien de neuf)

- **Un seul module** `apps/ia/app/services/data_sources/job_aggregators.py` (une entrée `SOURCE_REGISTRY`), trois
  fonctions, une par fournisseur, et `it_job_signals_aggregators(company, …)` qui les rassemble.
- **Même contrat de sortie** que France Travail / APEC / WTTJ (`title`, `location`, `date`, `contractType`,
  `skills`, `company`, `city`, `url`, `source`), fusionné ADDITIVEMENT dans `phase1_research.py` par
  `merge_job_signals` — **dédoublonnage par URL** avec les sources existantes.
- **Attribution sur preuve** : `employer_match.same_employer` (comme WTTJ) — une offre dont l'employeur n'est pas
  l'entreprise cherchée est écartée.
- **Tri métier** : le même que les autres sources (domaine du profil, placement CDI), passé par le routeur.
- **Sans clé = no-op STRICT** (zéro appel réseau). Débit : seaux `adzuna` / `jooble` / `theirstack` / `mantiks` / `fantastic_jobs`
  (`rate_limiter.py`). Coût : `provider_pricing.py` (TheirStack au résultat rendu, les deux autres gratuits).
- Le libellé de source n'est jamais montré comme « notre fournisseur » : la ligne d'offre porte l'URL de l'annonce.
