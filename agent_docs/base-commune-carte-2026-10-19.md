# Base commune — carte de la collecte partagée (#4268.a, 19/10/2026)

Décision Louis 19/10/2026 (décision 18 de `docs/briefs/vague-4-19-10.md`, écrite dans
`agent_docs/doctrine.md` à la suite de c94) : ce que Bellum collecte ou calcule pour un accès
— entreprises, personnes PUBLIQUES, signaux, tendances — profite à TOUS les espaces, sans
nouvelle collecte. JAMAIS partagé : ce qui concerne l'ESN ou l'utilisateur (CRM, prix et coûts
d'accès — GA-43 —, messages, notes, corrections, plans, consultants/CV, comptes suivis).
Une personne effacée (c67) reste effacée pour tous.

Cette carte est relevée dans le code de `origin/main` du 19/10/2026 (e41bc2ef79). Chaque ligne
porte son `fichier:ligne`. « Commun » = la clé ne porte ni espace ni utilisateur.

## 3. Ce qui est encore cloisonné — et ce que fait le lot

1. **Enrichissement d'une fiche à la demande** (`ContactsService.enrichContact`, `contacts.service.ts:4322`) :
   l'appel payant Apollo part (`contacts.service.ts:4416`) puis la cascade payante, SANS lire
   `shared_person_coordinates`. La base commune n'est relue qu'à la recopie d'une analyse : une fiche
   importée, saisie, ou analysée AVANT que la coordonnée soit versée, repaie. Les deux caches communs
   (Redis) s'évincent et expirent à 30 j ; la table durable, elle, reste. **#4268.b** : la lecture
   consulte d'abord le commun (fraîcheur = la règle de cache existante, 30 j `CACHE_TTL_CONTACT_S`),
   aucun débit, aucune copie de donnée privée (seule la coordonnée PRO d'origine Bellum, déjà frontiérée).
2. **Cache de résultat d'analyse C1** (`accounts.service.ts:5740`, `findCompletedByUserAndCompany`) :
   borné à l'ESPACE, et c'est VOULU — le dossier complet mêle le public (sources, déjà communes
   ci-dessus) et le propre à l'ESN (angles, plan, contacts annotés, messages). Copier le dossier serait
   copier de la donnée privée : refusé par la décision elle-même. Ce qu'une seconde analyse d'une même
   société repaie aujourd'hui, c'est le calcul personnalisé (classe B/C de `llm_response_cache.py`), pas
   la collecte.
3. Rien d'autre : toute source de collecte publique du § 1 est déjà commune.

## 4. Ce qui ne se partage jamais (la liste que GA-415 tient)

`packages/contracts/src/schemas/workspace-private-tables.ts` (#4268.c) : CRM (affaires, activités,
notes), messages et brouillons, prix et coûts d'accès (`access_facts`), corrections (organigramme,
provenance), plans, consultants / CV, comptes suivis. Un module de partage (`modules/shared-base/`) qui
les lit sans borne d'espace fait rougir **GA-415** (`apps/api/src/architecture/ga-415-base-commune-tables-privees.spec.ts`).

## 6. Le fait traverse, la trace jamais — l'inventaire d'une personne (#4800, Louis 29/10/2026)

Arbitrage : un fait public d'une personne (poste, employeur, ancienneté) se mutualise ; QUI l'a cherchée,
QUI l'a contactée et ce que l'accès a COÛTÉ restent à l'espace (GA-43).

**1. L'inventaire** — `packages/contracts/src/schemas/shared-person-fields.ts`, tenu par la garde **GA-418**
(`apps/api/src/architecture/ga-418-fait-public-trace-jamais.spec.ts`) :

| Champ de la fiche (`contacts`)                    | Nature               | Colonne commune                                          |
| ------------------------------------------------- | -------------------- | -------------------------------------------------------- |
| `full_name`, `title`, `linkedin_url`              | **fait**             | `shared_company_people.full_name / title / linkedin_url` |
| `lifecycle_state`, date de passage à l'historique | **fait**             | `employment_state`, `left_at`                            |
| `email`, `phone` (pro, trouvés par Bellum)        | **fait**             | `shared_person_coordinates.email / phone`                |
| `workspace_id`, `user_id`, `assigned_to`, …       | **trace** (qui)      | aucune                                                   |
| `email_cost_credits`, `phone_cost_credits`        | **trace** (coût)     | aucune                                                   |
| `email_sent_*`, `email_send_*`, `email_bounce*`   | **trace** (contacté) | aucune                                                   |
| `user_status`, `note`, `tags`, `crm_*`            | **trace** (travail)  | aucune                                                   |
| `last_enrichment_provider`, `enrichment_trace`    | **trace** (comment)  | aucune                                                   |

La garde sait dire NON : une colonne commune qui est une trace ou qui n'est pas classée, une nouvelle
colonne de fiche à la FORME d'une trace (espace, utilisateur, coût, envoi, « par qui ») non déclarée, un
INSERT du partage qui écrit une colonne non déclarée.

**2. L'effacement RGPD traverse (c67, #2297)** — déjà là, prouvé : `PersonErasureService` pose l'empreinte
dans `shared_person_erasures` et purge la base commune (`shared-company-facts-writes.ts:296-311`,
`person-erasure.service.ts:304`) ; le versement la relit (`shared-company-facts.service.ts:171`) et la
recopie aussi (`shared-company-facts-writes.ts:142`). Tests : `shared-company-facts-writes.spec.ts:118,182`.

**3. Une correction humaine gagne toujours, y compris contre un fait mutualisé plus récent** — déjà là
pour la coordonnée (#4268.d) ; **prouvé ici pour le poste** (`contacts.service.spec.ts`, « #4800.3 ») : un
poste corrigé à la main ne cède pas devant le poste plus long d'un fait `shared_base` (arbitre
`applyFieldUpdates`, `mergeSeedInto`), et le même fait sans correction l'enrichit. Côté versement, une
fiche corrigée à la main repart comme apport utilisateur anonymisé (`shared-company-facts.service.ts`, `human_corrected`).

**4. Les tendances de marché** — déjà là (c127, 22/10/2026) : agrégats sur jetons fermés, publiés à k ≥ 3
espaces, aucune ligne qui remonte à un espace (`market-pattern.ts`, garde GA-416
`ga-416-market-pattern-agregat-ferme.spec.ts`).

**5. Commune → département** (#4793.5, lot G) — `departmentsOfCity(nom)` / `cityInDepartments(nom, depts)` dans
`packages/contracts/src/schemas/geo-communes.ts`, importés par `@bellum/contracts/geo-communes` (hors de l'index : 438 Ko,
l'API seule). Table générée depuis `geo.api.gouv.fr` (COG) par `packages/contracts/scripts/generate-communes-departements.mjs`.
Un nom homonyme rend TOUS ses départements (« Saint-Denis » ⇒ 11, 30, 93, 974), jamais un seul deviné ; inconnu ⇒ `[]`.
